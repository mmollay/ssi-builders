⚠️ ES6 Module SPA Problem

Die brutale Wahrheit über Browser Module & Single Page Applications

🔴 Das Problem

Aktuelles Habbi Search Setup:

  • SPA Navigation: index.html lädt Inhalte dynamisch via Hash Routes (#/category-admin, #/blacklist-admin)
  • ContentLoader: Lädt HTML via AJAX und injiziert ins DOM
  • ES6 Module: Jede Seite (category-admin-new.html, blacklist-admin-new.html) hat <script type="module">

Test Resultat (Playwright):

✅ Step 1: Navigate to Categories → 20 rows loaded

✅ Step 2: Navigate to Blacklist → 20 rows loaded

❌ Step 3: Navigate back to Categories → 0 rows!

Was passiert:

1. User navigiert zu /category-admin (erste Mal)
→ Browser lädt category-admin-new.html
→ ES6 Module werden geladen & ausgeführt
→ ListBuilder.render() wird aufgerufen
→ ✅ 20 rows angezeigt

2. User navigiert zu /blacklist-admin
→ Browser lädt blacklist-admin-new.html
→ ES6 Module werden geladen & ausgeführt
→ ListBuilder.render() wird aufgerufen
→ ✅ 20 rows angezeigt

3. User navigiert zurück zu /category-admin
→ ContentLoader lädt category-admin-new.html erneut
→ Browser CACHED das Module! 🚨
→ Module Top-Level Code wird NICHT erneut ausgeführt!
→ new ListBuilder() wird NICHT erneut aufgerufen!
→ ❌ 0 rows (leerer Container!)

🤔 Warum passiert das?

Browser ES6 Module Caching ist ein FEATURE, kein Bug!

ES6 Module Specification (ECMAScript 2015):

"Module scripts are evaluated only once, the first time they are imported.
Subsequent imports of the same module will use the cached module instance."

Beispiel:

// module.js
console.log('Module loaded!');
export const value = 42;

// app.js
import { value } from './module.js'; // Logs: "Module loaded!"
import { value } from './module.js'; // Logs: NOTHING (cached!)

Das Problem mit SPA + AJAX Content Loading:

  • Module Identity: Browser identifiziert Module via URL (z.B. /vendor/ssi-builders/src/ListBuilder.js)
  • Single Execution: Module Top-Level Code läuft nur EINMAL beim ersten Import
  • AJAX Injection: Wenn du HTML via AJAX lädst und ins DOM injizierst, werden <script type="module"> zwar neu geparst, aber die importierten Module sind gecached
  • State Problem: Wenn dein Module-Code Seiteneffekte hat (DOM manipulation, new Builder()), laufen diese nicht erneut

⚠️ Das ist NICHT spezifisch für SSI Builders - das ist ein fundamentales Browser-Verhalten für ALLE ES6 Modules!

💡 Die Lösungen

1. Full-Page Navigation

⭐⭐⭐⭐⭐ EMPFOHLEN

Pros:

  • Module werden bei jeder Navigation neu geladen
  • Keine komplexen Workarounds nötig
  • Browser History & Back/Forward funktionieren perfekt
  • SEO-freundlich (jede Seite hat eigene URL)
  • Funktioniert PERFEKT (Playwright Test passed!)

Cons:

  • Full Page Reload (minimal langsamer)
  • Sidebar/Header müssen auf jeder Seite dupliziert werden
Implementation:

// navigation.js
items: [
{ href: '/category-admin-new.html', ... },
{ href: '/blacklist-admin-new.html', ... }
]

// Keine AJAX! window.location.href!

Jede Seite hat:
- Eigene HTML-Datei
- Eigene <script type="module">
- Sidebar + Header (via Shared Component)

2. Production Build (Vite)

⭐⭐⭐⭐ EMPFOHLEN

Pros:

  • Vite bundelt alles in optimierte Chunks
  • Module Loading Issues verschwinden
  • Performance: Minified & optimiert
  • Code Splitting möglich

Cons:

  • Build Step nötig (npm run build)
  • Dev Experience: Rebuild für jeden Test
  • Löst das Problem nur in Production, nicht im Dev
Implementation:

// vite.config.js
export default {
build: {
rollupOptions: {
input: {
main: 'index.html',
category: 'category-admin-new.html',
blacklist: 'blacklist-admin-new.html'
}
}
}
}

$ npm run build
$ npm run preview // Testen

3. React/Vue Migration

⭐⭐⭐⭐⭐ LONG-TERM

Pros:

  • Framework managed Component Lifecycle
  • Proper Re-rendering & State Management
  • Industry Standard (Google, Meta, etc.)
  • SSI Builders würden als React Components wrappen

Cons:

  • Große Refactoring-Aufwand
  • Learning Curve für Team
  • Build Pipeline komplexer
Implementation:

// CategoryAdmin.tsx
import React, { useEffect } from 'react';
import { ListBuilder } from '@ssi/builders';

export function CategoryAdmin() {
useEffect(() => {
const list = new ListBuilder({...});
list.render();
return () => list.destroy(); // Cleanup!
}, []); // Runs on mount!

return <div id="list-container"></div>;
}

4. Manual Module Reload

⭐ NICHT EMPFOHLEN

Pros:

  • Theoretisch möglich mit Cache-Busting

Cons:

  • Hackig & fragil
  • import() mit ?timestamp funktioniert nicht zuverlässig
  • Browser kann Cache-Busting ignorieren
  • State Leaks zwischen Loads möglich
  • Debugging Nightmare
Implementation (NICHT tun!):

// ❌ Funktioniert NICHT zuverlässig!
const module = await import(
`./category-admin.js?t=${Date.now()}`
);

// Browser cached trotzdem manchmal!
// Vite Dev Server hat eigenes Caching!

5. IIFE Wrapper

⭐⭐ FUNKTIONIERT NICHT

Warum es nicht funktioniert:

  • IIFE läuft zwar mehrfach
  • ABER: import Statement im IIFE wird gecached!
  • Browser cached Module-URLs, nicht Function Calls
  • Gleiche Module = gleiche Instanz
Warum es NICHT funktioniert:

// ❌ Hilft NICHT!
(async function() {
// Diese Function läuft mehrfach
import { ListBuilder } from '...';
// ABER: Browser cached ListBuilder.js!
// ListBuilder Code läuft nur EINMAL!
})();

6. Global State Manager

⭐⭐ WORKAROUND

Pros:

  • Könnte funktionieren mit globalem Lifecycle Manager

Cons:

  • Komplexe Custom Implementation
  • Manuelles Cleanup Management
  • Memory Leaks Gefahr
  • Reinventing React/Vue
Implementation (zu komplex!):

// Global Lifecycle Manager
window.appManager = {
activeBuilders: [],
destroyAll() { ... },
register(builder) { ... }
};

// Bei Navigation:
window.appManager.destroyAll();
// Load new page...

🚀 Long-Term (6-12 Monate):

React Migration mit SSI Builders Integration:

React + SSI Builders

// SSI Builders React Wrapper
function useListBuilder(config) {
const containerRef = useRef(null);
const builderRef = useRef(null);

useEffect(() => {
// Mount
builderRef.current = new ListBuilder({
containerId: containerRef.current.id,
...config
});
builderRef.current.render();

// Cleanup on unmount
return () => {
builderRef.current?.destroy();
};
}, [config]);

return containerRef;
}

// Usage
function CategoryAdmin() {
const listRef = useListBuilder({
columns: [...],
dataSource: async () => {...}
});

return <div ref={listRef} />;
}

Fazit: ES6 Module Caching ist KEIN Bug - es ist ein Feature!
Deine Architektur ist professionell (SSI Builders), aber die Navigation-Strategie
muss an Browser-Verhalten angepasst werden. Full-Page Navigation IST die
richtige Lösung für Vanilla JS Apps. Für komplexe SPAs → Framework! 🎯
